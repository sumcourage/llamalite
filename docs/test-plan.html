执行摘要

本测试计划涵盖 LlamaLite 项目的全部功能模块，包括前端 React 组件、Zustand 状态管理、自定义 Hooks、Rust 后端命令/存储/模型、Python 下载脚本以及端到端业务场景。目标是通过多层次测试保障项目功能按预期发展。

E2E 集成测试场景

场景 1: 服务完整生命周期

优先级: 高

路径: 服务 → 新建 → 启动 → 停止 → 启动 → 重启 → 删除

  1. 新建服务 (名称/模型路径/参数配置)
  2. 验证列表显示 (已停止)
  3. 启动服务，验证状态变为运行中
  4. 验证日志显示启动信息
  5. 验证端口可访问
  6. 停止服务，验证状态变为已停止
  7. 重新启动，验证状态变为运行中
  8. 重启服务，验证短暂停止后重新运行
  9. 删除服务，确认对话框后验证移除

场景 2: 单服务约束验证

优先级: 高

  1. 服务 A 运行中，尝试启动服务 B
  2. 验证错误提示："服务已在运行中，请先停止当前服务"
  3. 停止 A 后启动 B，验证 B 运行中、A 已停止

场景 3: 参数配置与验证

优先级: 高

  1. 验证参数按类别分组 (通用/采样/服务)
  2. 验证默认值正确填充
  3. 测试温度超出范围 (10) → 错误提示
  4. 测试上下文大小低于下限 (100) → 错误提示
  5. 测试线程数低于下限 (0) → 错误提示
  6. 验证高级参数默认隐藏，展开后显示
  7. 不填写模型路径保存 → 失败提示

场景 4: 模型下载与取消

优先级: 高

  1. 搜索 HuggingFace 模型
  2. 选择模型和量化版本，点击下载
  3. 验证进度条实时更新 (百分比/速度/大小)
  4. 下载过程中取消，验证模型不保存
  5. 重新下载，等待完成
  6. 验证模型出现在本地列表，大小正确

场景 5: 模型删除引用检查

优先级: 高

  1. 删除被服务引用的模型 → 拒绝并提示
  2. 删除引用服务后，再次删除模型 → 成功

场景 6: 硬件检测与模型推荐

优先级: 中

  1. 页面加载时自动检测硬件
  2. 显示 CPU 核心数、内存大小
  3. 推荐模型按硬件级别分类
  4. 每个推荐模型有一键下载按钮

场景 7: 设置管理与环境检测

测试策略

分层测试策略

层级范围目标覆盖率工具
单元测试函数、类、组件≥ 80% 代码覆盖率Vitest, cargo test, pytest
集成测试Store + Hook + 命令100% 核心流程Vitest, Rust #[cfg(test)]
E2E 测试完整业务流程15 个关键场景手动执行

Mock 策略

  • Tauri API: 所有 @tauri-apps/api/core 调用通过 vi.mock 全局 mock，使用 vi.mocked(invoke) 控制返回值
  • 事件监听: @tauri-apps/api/event 的 listen 函数全局 mock，返回清理函数
  • Rust 测试: 测试纯函数逻辑 (build_args、get_recommendations)，不依赖 Tauri 运行时
  • Python 测试: 通过 capsys fixture 捕获 stdout，验证 JSON 输出格式

测试边界

  • 参数验证: 最小值/最大值/步长倍数/空值/无效选择
  • 状态转换: 停止→启动→运行→停止→错误等所有合法路径
  • 数据约束: 单服务运行、模型引用检查、日志上限 1000 条
  • 网络异常: invoke 失败时 store 的错误处理、硬件检测的 fallback
  • 并发: 多下载进度更新、多服务状态切换
